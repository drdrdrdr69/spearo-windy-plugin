# Контракт API ↔ плагин Windy

Публичная семантика `https://spearo.app/api/plugin/windy/*`, на которую опирается
плагин. Здесь только то, что видит клиент: поля, статусы, состояния ошибок и правила
клиентского кэша. Внутренняя кухня сервера в контракт не входит и меняться может
свободно, пока соблюдается написанное ниже.

## Легальность зон
- `status` ∈ {`banned`, `dormant`, `conditional`, `open`}. Семантика: `banned` — запрет
  действует сейчас; `dormant` — правило есть, но по календарю/часам сейчас не в силе
  (тогда приходит `statusWhenInForce` и заполнен
  `temporal{state, season, seasonRaw, hours, timeZone, inForce, expires}`);
  `conditional` — правило не удалось разобрать, отдаётся сырой текст оговорки;
  `open` — запрета нет.
- **Наличие даты (срок разрешения, сезон) само по себе не понижает статус.** Понижение
  до `dormant` — только когда правило действительно не в силе на момент запроса; до
  `conditional` — только когда правило нечитаемо. Срок, истекающий в будущем, — `banned`.
- Статус зоны в плагине совпадает со статусом той же зоны на карте сайта; расхождение —
  ошибка API, а не плагина.
- Плагин рисует: `banned` — красная заливка; `dormant` — серый пунктир и «вне сезона:
  запрет с … по …» (даты из `temporal`); `conditional` — жёлтый и сырой текст оговорки;
  `open` — зелёный. Неизвестное значение статуса трактуется как `conditional`, никогда
  как `open`.
- `temporal.inForce` — ISO-дата/датавремя начала действия (или `null`), не булево.
- Геометрия не упрощается, `zoom` на неё не влияет.

## Честность условий
- Нет значения → `null`. Ни нулей, ни средних, ни «примерно».
- `stale: true` ⇒ измеряемые поля `null`, заполнен `staleReason`; такое тело можно
  показать с пометкой, но нельзя кэшировать. Заглушки не выдаются за измерения.
- Поля, зависящие от точки (`nearest.*`, `distanceKm`, `zones.*`), считаются от
  запрошенной координаты и не наследуются от соседних точек.
- Вердикт `safety` описывает море; правовой запрет едет отдельно, в `zones`.
- Дней из прошлого в `days[]` не бывает.

## Ошибки и CORS
- Любой ответ (200/400/413/429/500/503/OPTIONS) несёт CORS-заголовки;
  `Access-Control-Expose-Headers: Retry-After` обязателен — иначе браузер не покажет
  клиенту `Retry-After`.
- 413 `bbox_too_large` → плагин показывает «приблизьте карту»; 429/503/сетевой сбой →
  «данные недоступны»; «зон нет» — только при `ok:true` и пустом наборе.
- Тесты клиента проверяют заголовки через CORS-фильтр (как их видит браузер), а не
  сырой ответ.

## Клиентский кэш плагина
- Кэшируются только ответы `ok:true && !stale`; 429/503 и `stale` не кэшируются,
  `Retry-After` соблюдается (до его истечения новых запросов нет).
- Кэш проверяется раньше бэкоффа: точка с валидным бандлом продолжает отвечать, пока
  по пути висит 429.
- Отменённый запрос (`AbortError` по решению пользователя) не переиспользуется и не
  считается ошибкой; таймаут — отдельный класс ошибки, показывает «недоступно».
- «Сегодня» выбирается по дате места из ответа; при наступлении нового дня в таймзоне
  места бандл считается устаревшим и перезапрашивается.
- Смена дня при незавершённом запросе не отменяет общий бандл: ждём тот же промис.
